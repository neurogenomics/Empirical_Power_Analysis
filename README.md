## Overview

This repository contains the complete analysis pipeline used to empirically measure detection power for pseudobulk differential expression in human brain single-nucleus RNA-seq. The PsychAD cohort (1,494 donors before filtering) is split ten times into sex-stratified halves: one half defines the ground truth, and the other is systematically downsampled across a grid of donor count × cells per donor (and, separately, donor count × UMI budget). Every pseudo-experiment is analysed with three DE packages (DESeq2, edgeR and limma-voom) on identical samples, and recall and precision are scored against the ground-truth half. Sex-biased expression is used as the case-control variable because cohorts split close to 50:50 and sex-biased genes give a reproducible ground truth.

Outputs include:

- The empirical recall/precision dataset across the design space, per cell type and DE method, for three glial cell types (astrocytes, microglia, oligodendrocytes), with continuous (interpolated) surfaces.
- A gradient-boosted (XGBoost) per-gene power model with a dependency-light `predict_power()` wrapper for study design.
- A gene-level detectability classification (transcription-factor families, PANTHER protein classes, loss-of-function intolerant genes).
- A one-command pipeline (`pipeline/`) that regenerates every figure, table, quoted number and supplementary data file from the raw data.

## Scientific scope

- **Dataset:** PsychAD (Fullard et al., 2025), dorsolateral prefrontal cortex, 1,494 donors before filtering. After filtering (age ≥ 40 years, ≥ 30 cells per donor): 1,293 astrocyte donors, 1,214 microglia donors and 1,303 oligodendrocyte donors. See `Datalink/Dataset_Statistics_Table/Supplementary_Table_1_Dataset_Characteristics.csv`.
- **Case-control variable:** Sex. Chosen because (i) sex is close to 50:50 in brain cohorts; (ii) sex-biased genes are well documented and reproducible; (iii) the small-effect sex-biased genes are predominantly autosomal, which supports extrapolation to other contrasts.
- **DE methods:** DESeq2, edgeR and limma-voom on pseudobulk aggregates, design `~ source + ethnicity + disease + pmi_scaled + age_scaled + sex`. All log fold changes are shrunk with ashr so effect sizes are comparable across methods. Significance is BH-adjusted p < 0.05; the ground-truth set additionally requires |LFC| > 0.2.
- **Grid:** 12 donor counts (5-600) × 14 cells-per-donor levels (5-3,000 plus all available cells), 20 iterations per grid point, 10 robustness runs. The paper's primary grids pool detection outcomes across all three methods (`all_methods/`); per-method grids are in the supplement.
- **Power model:** Gradient-boosted decision-tree ensemble (XGBoost), trained on the realistic design regime (≥ 100 cells per donor). It predicts each gene's detection probability from |LFC|, mean expression, dispersion, donor count, cells per donor, UMIs per cell, DE method and cell type. A dependency-light `predict_power()` wrapper, the fitted model (`power_model_bundle.rds`) and an example power curve are shipped in `Datalink/Power_Curve_Fitting/Exports/xgboost/realistic/`, so the wrapper runs without refitting. See [`docs/model-card-predict_power.md`](docs/model-card-predict_power.md).

## Key findings

Effect-size bins: tiny (|LFC| 0.2-1), small (1-2), medium (2-3), large (> 3).

1. **Genes with |LFC| < 2 did not reach 80% pooled recall anywhere in the design space**, even with 600 donors and all available cells. Tiny-effect genes needed 75 donors to reach 10% recall, reached 21% at 200 donors and never exceeded 42%.
2. **Large-effect genes reached 80% recall with as few as 15 donors** when at least 1,500 cells per donor were available.
3. **Only the most significant ground-truth genes were robustly recovered.** Recall falls sharply from the top to the bottom adjusted-p-value quartile, although every truth gene passes padj < 0.05, and mean expression strongly determines recall.
4. **Recall ranks microglia > astrocytes > oligodendrocytes**, anticorrelated with the amount of data per cell type. Reducing astrocytes to microglial cells per donor and UMIs per cell lost roughly 55% of ground-truth DEGs for DESeq2 and edgeR. Reducing cell numbers cost more DEGs than matching UMI depth, so maximising cells per donor matters more than deeper sequencing.
5. **The power model is reliable at the extremes but not in the contested middle.** 97.6% and 98.0% of predictions in the 0-0.1 and 0.9-1 bands fall within 0.10 of the observed detection rate, while the 0.2-0.8 band has a mean absolute error of 0.22-0.24. Only 7.8% of grid points fall between 0.1 and 0.9, so a skewed three-class (underpowered / contested / powered) output is recommended.

## Reproducing the analysis

### Full reproduction from raw data (recommended)

`pipeline/` rebuilds every figure, table, quoted number and supplementary data
file, and knits the manuscript, from the raw PsychAD files in one command on a
PBS Pro cluster (written for Imperial CX3). All of it runs inside the pinned
container. See **[`pipeline/README.md`](pipeline/README.md)**.

```bash
pipeline/reference/fetch_reference.sh $WORK/reference   # offline annotation bundle
pipeline/run.sh $WORK                                    # submits the whole chain
pipeline/run.sh $WORK --status
pipeline/unpack_results.sh $WORK/results /path/to/checkout   # afterwards, anywhere
```

The sections below describe running individual pipelines by hand.

### Requirements

- **R 4.5.1** with **Bioconductor 3.22**. Every R package is pinned in `renv.lock`; restore it with:

  ```r
  install.packages("renv")
  renv::restore()
  ```

- The DE and modelling core is DESeq2, edgeR, limma, ashr, glmGamPoi and xgboost; reading the raw h5ad files uses zellkonverter with a Python environment (anndata, h5py, numpy, pandas, scipy) pinned in `docker/python-requirements.txt`.

The container below provides all of this, and is the supported way to get an exact environment. Each `R/<pipeline>/config.R` loads only the packages it needs.

### Resolving the project root

Each pipeline's `config.R` detects the project root automatically via `here::here()`. You can override this with the `POWER_ANALYSIS_ROOT` environment variable, which is useful when running on clusters where the working directory is not the repo root:

```bash
export POWER_ANALYSIS_ROOT=/path/to/this/repo
```

### Data prerequisites

This repository ships **final figures, paper source data, Supplementary Data and the fitted power model** only. Every input to the analysis is already openly available (the PsychAD data on CELLxGENE, plus public reference annotations fetched by `pipeline/reference/fetch_reference.sh`), so we deliberately do not deposit a separate copy of the raw data or of the intermediate artefacts (donor shards, DE checkpoints, BioMart caches, the 10-run grid). Instead, the pipeline regenerates every intermediate from those public sources, with the raw files verified against `pipeline/inputs.sha256`. Each pipeline's scripts create their output subdirectories on first run.

The raw inputs are the three PsychAD h5ad files (`PsychAD-HBCC.h5ad`, `PsychAD-MSSM.h5ad`, `PsychAD-RADC.h5ad`) from [CELLxGENE collection 84ce6837](https://cellxgene.cziscience.com/collections/84ce6837-548d-4a1f-919f-0bc0d9a3952f), plus the PsychAD donor table with post-mortem interval (`media-1.csv`, a supplementary table of Fullard et al. 2025). Checksums are in `pipeline/inputs.sha256`. For the manual route, place them under `Datalink/raw_data/`.

Each pipeline's `README.md` documents its expected inputs and its outputs.

### Run order

Pipelines form a DAG rooted at sharding. `pipeline/stages.tsv` is the authoritative stage graph; by hand, the order is:

```
1. R/sharding/                  # Raw PsychAD → donor-level shards under Datalink/Shards/
2. R/eda_roussos/               # PCA gallery, read-depth summary, sex-label validation
3. R/full_ground_truth/         # Full-cohort DE and gene-universe audit
4. R/cartesian_downsampling/    # Detection outcomes across the donor × cell (and UMI-budget) grid, 3 methods × 10 runs
5. R/depth_equalization/        # Depth-equalised astrocyte sets and DEG-loss analysis
6. R/power_curve_fitting/       # XGBoost power-model fitting, selection, SHAP, and export
7. R/de_diagnostics/            # Chromosome grid + shared-gene diagnostics
8. R/gene_classification/       # Figure 6 gene detectability classification
9. R/figure_data_generation/    # Canonical CSVs consumed by the paper
10. R/figure_composition/       # Composed multi-panel figures
11. R/supplementary_data/       # Supplementary Data files
```

The cartesian grid (step 4) is by far the most expensive step and in practice needs a cluster.

### Running a pipeline

Most pipelines contain a `run_pipeline.R` master runner. Example:

```bash
Rscript R/cartesian_downsampling/run_pipeline.R            # Run all steps
Rscript R/cartesian_downsampling/run_pipeline.R 3,7 16     # Run steps 3 and 7 on 16 cores
```

Individual steps (e.g. `01_Generate_Ground_Truth.R`, `02_Run_Downsampling_Grid.R`) can also be invoked directly.

### Containerised reproduction (Docker / Apptainer)

For a reproducible environment, run the pipeline inside the pinned container instead of installing packages by hand. The image is built from a digest-pinned Bioconductor base with every R package restored from `renv.lock`, every apt package pinned in `docker/apt-packages.txt` and every Python dependency installed with hashes. Full details are in [`docs/docker.md`](docs/docker.md).

The wrapper scripts live in `docker/` and are run from the repo root:

```bash
# Build the image, verify the environment, then run the default pipeline:
./docker/docker-all.sh                         # build + smoke-test + run power-curve fitting

# Just verify the image builds and every package loads (no pipeline):
./docker/docker-all.sh --skip-run

# Already built? Skip ahead and run a specific pipeline:
./docker/docker-run.sh --pipeline all --max-cores 24
./docker/docker-run.sh --pipeline pcf                 # power-curve fitting only

# Long unattended run:
nohup ./docker/docker-all.sh --pipeline all --max-cores 24 > nohup.docker-all.out 2>&1 & disown
```

The individual wrappers (`docker/docker-build.sh`, `docker/docker-smoke.sh`, `docker/docker-run.sh`) can be called separately; `docker/docker-all.sh` chains them with `--skip-build` / `--skip-smoke` / `--skip-run` flags.

**On HPC (no root):** the same image runs under Apptainer. Build the `.sif` with `./docker/build-sif.sh` (from a local Docker image, or `--from-registry` for a published one) and give it to `pipeline/run.sh`.

### HPC (Imperial CX3, PBS Pro)

Use `pipeline/` (above). It submits every stage as a dependency-chained PBS job,
stages data through node-local scratch as a few large tars, and resumes from
wherever a previous attempt stopped. The older hand-driven scripts in `hpc/`
are kept for reference only.

### Reproducibility snapshot

The `Reproducibility/` directory records the environment of the analysis server:

| File | Contents |
| --- | --- |
| `project_packages.csv` | Every package loaded by the pipeline with its pinned version |
| `installed_packages.csv` | Full `installed.packages()` dump of the build environment |
| `session_info.txt` | `sessionInfo()` including BLAS/LAPACK, locale, `.libPaths` |
| `system_info.txt` | R version, `Sys.info()`, `capabilities()`, `extSoftVersion()` |
| `server_specs.txt` | Host OS, kernel, CPU, RAM, disk layout of the analysis server |

To regenerate the snapshot on another machine:

```bash
Rscript R/shared/capture_environment.R
```

A `pipeline/` run also writes its own `results/PROVENANCE.txt` and `results/MANIFEST.sha256`.
