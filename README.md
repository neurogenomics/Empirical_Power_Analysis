Code and paper-ready figures accompanying:

> **Single-Cell Study Designs Are Systematically Underpowered for Small-Effect Genes**
> Chris Crampton, Salman Fawad, Toby Clark, Hiru Dash, Bence Kövér, Garry Cotton, Donghoon Lee,  Eugene Duff, Leonardo Bottolo, Paul Matthews, Nathan Skene

## Overview

This repository contains the complete analysis pipeline used to empirically measure detection power for pseudobulk differential expression in human brain single-nucleus RNA-seq. The PsychAD cohort is systematically downsampled across a two-dimensional grid of donor count × cell count (and separately, donor count × reads per cell), producing over 22 million per-gene detection outcomes. Sex-biased expression is used as a reproducible case-control variable with a biologically grounded ground truth.

Outputs include:

- Continuous recall and precision surfaces across the experimental design space for three glial cell types (astrocytes, microglia, oligodendrocytes).
- Cross-dataset validation against four independent snRNA-seq cohorts (Allen/SEA-AD, DeJager/ROSMAP, Rexach, Johansen) and a GTEx v8 bulk RNA-seq reference.
- A gradient-boosted (XGBoost) per-gene power model with a dependency-light `predict_power()` wrapper for study design.

## Scientific scope

- **Primary dataset:** PsychAD (Fullard et al., 2025), filtered to 1,293 astrocyte donors, 1,214 microglia donors, and 1,303 oligodendrocyte donors. See `Datalink/Dataset_Statistics_Table/Supplementary_Table_1_Dataset_Characteristics.csv`.
- **Validation datasets:** SEA-AD (Allen), ROSMAP (DeJager), Rexach, Johansen — used for cross-dataset IoU, sign, and LFC agreement.
- **Bulk reference:** GTEx v8 (838 donors across 44 tissues) for external LFC calibration.
- **Case-control variable:** Sex. Chosen because (i) sex is close to 50:50 in all brain cohorts; (ii) a well-characterised set of sex-biased genes (principally on the sex chromosomes) provides a reproducible ground truth; (iii) sex-biased DE generalises across independent cohorts.
- **DE methods:** DESeq2, edgeR, and limma-voom, each run on pseudobulk aggregates. The paper's primary recall/precision grids pool detection outcomes across all three methods (`all_methods/`); per-method grids are provided in the supplement. DESeq2 additionally applies apeglm LFC shrinkage.
- **Power model:** Gradient-boosted decision-tree ensemble (XGBoost), trained on the realistic design regime (≥ 100 cells per donor). It predicts each gene's detection probability from |LFC|, base mean, dispersion, donor count, cells per donor, reads per cell, DE method, and cell type. A dependency-light `predict_power()` wrapper, the fitted model binary (`power_model_bundle.rds`), and an example power curve are exported under `Datalink/Power_Curve_Fitting/Exports/`, so the wrapper runs without refitting.

## Key findings

1. **Small-effect genes (|LFC| 1–2) never exceeded 80% pooled recall** across the entire experimental space, including 600 donors with all available cells. The tiny-effect bin (|LFC| 0.2–1.0) never exceeded 43% recall.
2. **Large-effect genes (|LFC| > 3)** reached 80% recall with as few as 10–15 donors, provided ≥750 cells per donor were available.
3. **The apparent cell-type power hierarchy (microglia > astrocytes > oligodendrocytes) is an artefact of DESeq2 independent filtering.** Depth equalisation (downsampling astrocytes to microglia-equivalent reads per cell) inverts the hierarchy, showing that cellular yield per donor is more determinative than per-cell sequencing depth. Oligodendrocytes, with 96% of genes testable after independent filtering, provide the most conservative power estimates.
4. **Sex-biased DE is reproducible across independent cohorts.** Universe-controlled IoU values between PsychAD and four external datasets range from 0.60 to 0.92, approaching the 0.65–0.87 split-half ceiling.

## Reproducing the analysis

### Full reproduction from raw data (recommended)

`pipeline/` rebuilds every figure, table, quoted number and supplementary data
file, and knits the manuscript, from the raw PsychAD files in one command on a
PBS Pro cluster (written for Imperial CX3). All of it runs inside the pinned
container. See **[`pipeline/README.md`](pipeline/README.md)**.

```bash
pipeline/reference/fetch_reference.sh $WORK/reference   # offline annotation bundle
pipeline/run.sh $WORK                                    # submits the whole chain
pipeline/run.sh $WORK --status
pipeline/unpack_results.sh $WORK/results /path/to/checkout   # afterwards, anywhere
```

The sections below describe running individual pipelines by hand.

- **R** ≥ 4.2

`DESeq2`, `edgeR`, `limma`, `apeglm`, `SingleCellExperiment`, `SummarizedExperiment`,
`BiocParallel`, `biomaRt`, `AnnotationDbi`, `org.Hs.eg.db`, `rhdf5`,

`R/<pipeline>/config.R` loads the packages it actually needs.

### Resolving the project root

Each pipeline's `config.R` detects the project root automatically via `here::here()`. You can override this with the `POWER_ANALYSIS_ROOT` environment variable, which is useful when running on clusters where the working directory is not the repo root:

```bash
export POWER_ANALYSIS_ROOT=/path/to/this/repo
```

### Data prerequisites

This repository ships **final figures and paper source data only**. Raw inputs (h5ad / h5Seurat files) and most intermediate artefacts (donor shards, DE checkpoints, BioMart caches) are not distributed here owing to size and dataset-specific access terms. The fitted power-model bundle (`Datalink/Power_Curve_Fitting/Exports/xgboost/realistic/power_model_bundle.rds`) is the one exception: it is shipped so that `predict_power()` runs out of the box without refitting. Every intermediate is regenerable from the raw data — each pipeline's scripts create their required output subdirectories on first run.

Download the raw datasets from the public sources listed in `Datalink/Dataset_Statistics_Table/Supplementary_Table_1_Dataset_Characteristics.csv` and place them under `Datalink/raw_data/`. One of the validation datasets is not publicly available and must be obtained directly from the upstream authors under their access terms; the pipeline will skip it gracefully if absent.

Each pipeline's `README.md` documents its expected inputs (normally under `Datalink/` subdirectories) and its outputs.

### Run order

Pipelines form a DAG rooted at sharding. To reproduce from raw data end-to-end:

```
1. R/sharding/                  # Raw data → donor-level shards under Datalink/Shards/
2. R/eda_roussos/               # PCA gallery, read-depth summary, filtering summary
3. R/full_ground_truth/         # Ground-truth DE (DESeq2 / edgeR / limma-voom) per dataset + cross-dataset diagnostics
4. R/cartesian_downsampling/    # 22M detection outcomes across the donor × cell grid
5. R/depth_equalization/        # Depth-equalised astrocyte downsampling (optional sensitivity analysis)
6. R/power_curve_fitting/       # XGBoost power-model fitting, selection, SHAP, and export
7. R/de_diagnostics/            # Chromosome grid + shared-gene diagnostics
8. R/bulk_deg_processing/       # GTEx bulk processing + bulk-vs-scRNA concordance
9. R/figure_data_generation/    # Canonical CSVs consumed by the paper
```

Steps 7–9 can run in any order once 3–6 have completed.

### Running a pipeline

Every pipeline contains a `run_pipeline.R` master runner. Example:

```bash
Rscript R/cartesian_downsampling/run_pipeline.R            # Run all steps
Rscript R/cartesian_downsampling/run_pipeline.R 3,7 16     # Run steps 3 and 7 on 16 cores
```

Individual steps (e.g. `01_Generate_Ground_Truth.R`, `02_Run_Downsampling_Grid.R`) can also be invoked directly.

### Containerised reproduction (Docker / Apptainer)

For a byte-reproducible environment, run the pipeline inside the pinned container instead of installing packages by hand. The image is built from a digest-pinned Bioconductor base with every R package restored from `renv.lock` and every Python dependency installed with hashes. Full details are in [`docs/docker.md`](docs/docker.md).

The wrapper scripts live in `docker/` and are run from the repo root:

```bash
# Build the image, verify the environment, then run the default pipeline:
./docker/docker-all.sh                         # build + smoke-test + run power-curve fitting

# Just verify the image builds and every package loads (no pipeline):
./docker/docker-all.sh --skip-run

# Already built? Skip ahead and run a specific pipeline:
./docker/docker-run.sh --pipeline all --max-cores 24
./docker/docker-run.sh --pipeline pcf                 # power-curve fitting only

# Long unattended run:
nohup ./docker/docker-all.sh --pipeline all --max-cores 24 > nohup.docker-all.out 2>&1 & disown
```

The individual wrappers (`docker/docker-build.sh`, `docker/docker-smoke.sh`, `docker/docker-run.sh`) can be called separately; `docker/docker-all.sh` chains them with `--skip-build` / `--skip-smoke` / `--skip-run` flags.

**On HPC (no root):** the same image runs under Apptainer. Build the `.sif` with `./docker/build-sif.sh` (from a local Docker image, or `--from-registry` for a published one) and give it to `pipeline/run.sh`.

### HPC (Imperial CX3, PBS Pro)

Use `pipeline/` (above). It submits every stage as a dependency-chained PBS job,
stages data through node-local scratch as a few large tars, and resumes from
wherever a previous attempt stopped. The older hand-driven scripts in `hpc/`
are kept for reference only.
